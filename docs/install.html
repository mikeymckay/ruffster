Getting started

A clear path for families—and contributors.

The family installation is still being built. This guide separates what families should expect from developer testing instructions, so an experimental preview is not mistaken for a supported release.

There is no supported family installer yet. The current Mac app is unsigned, the Windows setup has not run on a Windows computer, and the parent and child experiences have not been tested with families. Do not install this prototype for ongoing monitoring of a child.

For parents

Wait for a supported release. There is no public download, signing and notarization are unfinished, Windows behavior is unverified, and independent security, privacy, accessibility, and usability reviews remain open.

The intended flow is designed to be straightforward:

  1. Start on the parent's computer. Choose a six-digit parent access PIN that your child does not know. Save the encrypted recovery copy somewhere you control before setting up the child's computer. The child's computer can lock reports for you, but it cannot open them.
  2. Set up the child's computer together. Read what is recorded together, choose how long to keep detailed records, and verify the visible status indicator. For setup, the parent computer shows two digits and the child computer enters them. When returning a report, the child computer shows two digits and the parent computer enters them. Both devices need the same Wi-Fi and local network discovery must be allowed. On a Mac, the system may ask to allow Ruffster to use the local network; this is only for finding the other computer and transferring the public key or encrypted report, not for activity monitoring. If access is denied, pairing cannot work until it is allowed in System Settings → Privacy & Security → Local Network. If the local network blocks report transfer, choose Save an encrypted report file in the child computer’s status menu, move the file to the parent computer, and choose Open a report file instead in the dashboard.
  3. Review an encrypted report. Return it to the parent computer, open it locally, and discuss observations and uncertainty together.

About website names: No browser add-on is needed on the parent's computer or to use the main app. The optional experimental add-on would run in selected browsers on the child's computer. A child can turn it off or use another browser, so website details may be missing; the report cannot tell you why. The add-on is not part of the supported setup.

The school does not need to install or operate the app. The first supported student platforms are planned to be macOS, then Windows. Linux is not a student-facing target.

Current preview status

macOS

An unsigned Apple-silicon development bundle can be built from source. It includes a local parent dashboard, experimental encrypted collection, and a disclosed setup flow. On the test Mac, a temporary synthetic-only test verified encrypted app samples, a recorded coverage gap, the real installer's same-location update restart, launchd recovery after forced termination, and clean uninstall with the report retained. It collected no real app or network data and removed its temporary service and files. The menu-bar display and VoiceOver behavior, native setup dialogs, physical sleep/wake, signing, notarization, and family usability remain unverified. The preview is for development only.

Windows

A Windows x64 setup and tray companion, parent dashboard launcher, and collection adapters are in development. The companion has been cross-compiled, but no Windows computer has run the package. Do not use it for family monitoring.

For contributors

Use a recent Python 3 and a virtual environment. Linux is supported as a convenient development/test host; tests there do not prove macOS or Windows behavior. 

python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m unittest discover -s tests -v
node --check family_activity/parent_assets/app.js

For a Mac bundle, use a Mac with PyInstaller and the project dependencies installed: 

./scripts/build-macos-preview.sh \
  "$(pwd)/.venv/bin/python" \
  "/absolute/path/to/output-directory"

For the Windows preview, build on Windows x64 with Python, PyInstaller, and the .NET 10 LTS SDK. From the repository root, run python -m pip install -e ".[build]" and then ./scripts/build-windows-preview.ps1 -OutputDirectory ./dist/FamilyActivityPreview in PowerShell. The Windows builder also creates a direct-download per-user installer that copies its files and then opens family setup; monitoring still requires family confirmation. Linux cross-compilation checks that executable can be built, but cannot run Windows extraction, setup, or tray behavior.

When family releases are ready

A release download will appear only after the supported operating-system flows are tested, the packages are signed, and clear installation, update, removal, data export, key recovery, and deletion instructions are in place. Until then, the project status page in the source repository describes the open validation work.

Never treat missing data as evidence. A sleep, crash, network change, permission issue, removal, or other event can create a gap. The prototype cannot establish its cause or resist an administrator who changes the computer.
