Questions, answered plainly

Know what is collected—and what it cannot show.

Family Activity is meant to make technology use easier to discuss. These answers describe the current prototype and its limits, not a promise that a final product is ready.

Is Family Activity ready to install on my child's computer?

No. The Mac bundle is unsigned, the Windows package has not been run on Windows, and the experience has not been validated with families. See the getting-started guide .

What does it collect?

The experimental encrypted agent samples the foreground application name and total byte counts reported by network interfaces. The Mac setup and experimental Windows preview also create a device-only random key for a pseudonymous hint when the default router changes; the raw router address is not saved, and the hint does not establish location. It records monitoring sessions and gaps that can be observed. An optional, experimental Chromium extension can send active website domains; a visible popup explains this and lets the child pause website observations. It does not inspect private-window domains or send complete URLs, page titles, or page contents. When the child returns to a regular window after private browsing, a domain-free marker may be sent to prevent website-time estimates from spanning that interval. It stores whether website observations are paused and a temporary note to keep time estimates from stretching across gaps; it does not keep domain history in the browser. If a report has no domains, it cannot tell whether the extension was paused, disconnected, or did not observe a website. DNS and proxy settings are reduced to simple indicators. Exact behavior varies by operating system and remains under validation.

What does it never collect?

The product does not capture screenshots, keystrokes, audio, camera data, message contents, or full website URLs. It is designed for transparency, not hidden surveillance or automatic blocking.

Do I need a browser add-on, and whose computer is it for?

No. The main app and parent dashboard work without a browser add-on. The optional experimental add-on runs on the child's computer, inside each supported browser the family chooses to include; it does not go on the parent's computer. It can show the names of websites used in those browsers, because the computer's overall internet totals cannot name websites. The child can turn it off, remove it, or use another browser. Website details will then be missing, and the report cannot say why. Missing details are not evidence of avoidance or misconduct. The add-on is not part of setup and is not yet available as a supported family install.

Can it tell how much data a particular website used?

No. The report adds recorded counter changes separately for each network interface, but interfaces can overlap and missed intervals may leave traffic uncounted. Labels such as “en0” are computer-generated connection IDs, not website names; a VPN and its Wi-Fi connection may count the same traffic. A domain sample and a byte counter are separate observations; the prototype must not combine them into claims such as “YouTube used 2.4 GB.”

What do the school-hours and network-label estimates mean?

School-hours traffic is estimated by apportioning each measured interface-counter interval according to how much of it overlaps the schedule you chose. Separate Home-, School-, and Other-labeled network estimates use the most recently observed router label that you set. A School label is not the same as the schedule-based school-hours view, and neither proves where the computer was. Network-label estimates skip sample intervals with a recorded change; traffic estimates omit intervals ending at or crossing an observed router change. Labels can be wrong or unavailable. Views may overlap, and interface counters can overlap too, so do not add them together as a device-wide total.

Does a VPN or DNS indicator prove that filtering is working?

No. The indicators are incomplete. The Windows preview checks IPv4/IPv6 resolver settings and the signed-in account's Internet Settings proxy settings, plus connected status for built-in Windows VPN profiles; it does not inspect separate WinHTTP proxy settings, and third-party VPNs may not appear. macOS checks a different set of system-reported settings. A filter configured only on a home router normally applies only while the computer uses that router; by itself it does not follow to school Wi-Fi or a mobile hotspot. A device profile or filtering app may work on other networks if that setup supports them and remains allowed and active. VPNs, browser secure DNS, and school-managed settings can change which service handles DNS. Check the provider's own status or supported test separately on each network, and ask the school before changing a school-managed computer. This app cannot verify that filtering works. NextDNS describes device and router setup options as one example; review any provider's privacy and retention terms before choosing a service.

Is my child's information uploaded to a cloud service?

The prototype has no required cloud account. The handoff works the same way in either direction: the computer sending something shows two digits, and the receiving computer enters them. Both must be on the same Wi-Fi. The digits only find the nearby computer; they are not a password. The app creates a protected connection and sends only the parent's public key or an already-encrypted report. On a Mac, macOS may ask to allow local-network access; this is used only for finding the other computer and transferring the public key or encrypted report, not for monitoring. If access is denied, allow it in System Settings → Privacy & Security → Local Network. Local discovery may also be blocked by a network or firewall, and the transfer has not received an independent security review.

Who holds the encryption key?

New setups use a six-digit parent access PIN that the child should not know. It helps keep reports private from the child. If someone copies the recovery file, they can try PIN guesses, so don't treat this short PIN as protection from a determined attacker. The child's computer can lock reports for you, but it cannot open them. Save the encrypted recovery copy before setup. On a new parent install, choose “Restore parent access,” select the encrypted .vault file, and enter the same PIN. Older recovery copies can still be restored with their original phrase. Losing both the recovery copy and PIN means reports cannot be opened. There is no PIN recovery service.

Can it explain a monitoring gap or detect tampering?

No. A gap shows that observations were missed; it does not identify whether the cause was sleep, a crash, a permission change, an uninstall, or something else. A person with administrator access can change or disable software on their computer. This prototype is not tamper-proof.

Does the school need to set anything up?

No school installation or administration is intended. Families choose a school-hours schedule themselves. That schedule creates a time-based report and does not prove that the computer was at school.

Which computers are priorities?

macOS comes first, then Windows. Linux is used as a development and test host only; there are no plans for students to use the Linux version in the current scope.

What about plaintext files from an earlier prototype?

New agent runs require the parent's public key and write encrypted events. An older developer database may still contain plaintext; the app does not automatically change or delete it. Developers can use the documented encrypt-legacy command to create an encrypted copy of the supported prototype schema with a chosen retention period. The command leaves the original file untouched. Verify the encrypted copy before deciding how to remove the original; secure erasure from storage and backups is not guaranteed.

How long are reports kept, and can they be deleted?

The prototype has separate retention controls for the child computer and parent copy. It offers local report deletion, but exported backups and filesystem snapshots are outside those controls. Secure erasure from storage media is not guaranteed. A release needs reviewed retention, deletion, export, update, and recovery behavior on each supported platform.

Is the prototype legally compliant in Europe?

No claim of legal compliance is made. Children's privacy, transparency, consent, and data-minimization obligations depend on the people and context involved. Qualified legal and privacy review is still needed.
