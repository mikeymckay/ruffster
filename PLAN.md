# Implementation plan

**Device connection decision:** keep direct encrypted LAN transfer as the current path and encrypted report-file export/import as its fallback. Do not spend more work tuning subnet scans unless real supported-device validation identifies a specific gap. An optional cloud rendezvous service can later exchange short-lived connection candidates so devices can attempt a direct LAN connection; it must not carry report data or the parent private key. It cannot bypass LAN client isolation or blocked peer traffic. A cloud data relay is a separate later feature. Do not add compression to direct transfers; revisit it only if a future server data-relay design makes bandwidth or temporary storage a concern.

1. **Foundation (prototype complete):** local SQLite sessions and heartbeats, observable unclean-stop intervals, parent dashboard, automated tests and privacy documentation.
2. **macOS family-ready product (first platform priority):** foreground app snapshots, a heartbeat-backed status companion with starting/active/paused states, encrypted-only agent records, interface counters, router-change hints and minimized DNS/proxy/system VPN indicators are in the prototype. On the test Mac, a live synthetic-input check now verifies encrypted foreground sampling, an observed process-suspension gap, launchd restart under a new PID/session after SIGKILL, and clean bootout; the real installer has also been exercised end to end with the encrypted agent and synthetic-only foreground input, network collection disabled, launchd restart after SIGKILL, a recorded restart gap, and uninstall retaining the encrypted database by default; a separate harmless-process check still covers install rollback wiring. The companion now sets explicit accessibility labels and help for the three monitoring states; the changed helper compiled and passed its native self-check on the Mac. Its rendered label and actual VoiceOver behavior have not been reviewed interactively. The native welcome screen now separates preview readiness, collected data, privacy exclusions, and the parent/child next actions. Parent-key pairing reads network results off the setup UI thread and shows accessible progress with a cancel action. Install and removal use visible progress windows while stderr is drained in the background, and the app rejects quit while those operations run; the updated setup compiles on the Mac, but all windows still need interactive review. The current unsigned Apple-silicon app now builds from source on the test Mac, and the Mac build now runs `scripts/validate-macos-preview-bundle.py`, which starts its frozen parent runtime on loopback and verifies unauthenticated API rejection; this CI-ready smoke check starts no monitoring service and uses temporary parent data. The live agent validator also verifies cleanup after uncertain launchd registration and preserves synthetic fixtures if bootout fails. The native macOS CI package job is configured to run the separate harmless sleep-only LaunchAgent startup/restart/uninstall check. Physical sleep/wake, account switching, and permissions still need real-device validation. A private signed/notarized preview packaging path is implemented in `scripts/package-macos-candidate.sh`, but cannot run on the current Mac because it has no Developer ID identity; signing and notarization remain unvalidated. The collection CLI refuses to start without the parent's public key. Finish key recovery, safe updates/removal, accessibility, signing, notarization, and audit and resolve any pre-existing plaintext prototype files before supporting families.
3. **Lifecycle and parent reporting (prototype):** per-user launchd start/restart and removal, separate child and parent retention controls, one-use local public-key setup and encrypted report transfer, school-hour and Home-, School-, and Other-labeled router-hint app and website estimates plus estimated interface-byte context, protection guidance, and explicit local report deletion. A seven-day recorded-agent-runtime summary now counts session boundaries and observed gaps while excluding known gaps from the total. The parent dashboard can restore the encrypted parent-key backup on an empty parent install after checking the passphrase, without replacing an existing key. Before releasing any child setup public key, the dashboard requires the parent to download the encrypted key backup and confirm it was stored safely; the parent settings persist this acknowledgement and old settings default to unconfirmed. The review now leads with seven-day and school-hours summaries; today, category, network, and detailed coverage views are keyboard-accessible disclosures. Synthetic setup and report screenshots are regenerated from the current UI. A synthetic-key report transfer has worked over the home LAN between the test Mac and the Linux development host, and deletion paths have test coverage on both hosts. The packaged Mac parent app has now created an encrypted key backup and restored it into a fresh temporary profile on the test Mac; both private data directories passed permission checks. Next validate dialogs and lifecycle on Mac, Windows parent transfer when Windows is available, accessibility, and family usability.
4. **Windows family-ready product (second platform priority):** foreground and interface adapters, a packaged-agent Task Scheduler path, a graphical setup/removal wizard, a self-extracting per-user single-download installer that validates archive paths and opens the confirmation flow only after copying files, one-time pinned public-key pairing, a separate loopback parent-dashboard launcher, and encrypted report sharing from the visible tray are in the prototype. Setup now registers a per-user sign-in task, asks Task Scheduler to start it immediately, and waits for a new encrypted session event while the agent lock is held before reporting success. It preserves setup metadata if start or tray readiness fails, and the setup screen prevents a duplicate retry when registration may have succeeded. The installer creates a device-only HMAC key for pseudonymous IPv4 default-router hints and retains it alongside local encrypted data; setup and tray disclosures explain the data and its limits. This PowerShell route/neighbor lookup is covered by Linux mocks and source checks but has not run on Windows. The tray now shows starting/on/paused from a separate heartbeat event signaled after each stored encrypted sample; it fails closed if the helper or event disappears. The PowerShell package builder now constructs and lays out the first-run and removal forms, tests deferred program-folder cleanup against a synthetic locked file, exercises the tray starting/on/paused state transitions without showing a window, runs a Python-to-Win32 named-event heartbeat check, then registers a synthetic-only Task Scheduler job to verify encrypted sampling, crash restart, gap reconstruction, and normal uninstall; a separate frozen-core smoke test by launching its parent dashboard in a temporary profile, confirming loopback binding and an unauthenticated API rejection, saving a Europe/Vienna schedule, and rendering an encrypted test report; the Windows bundle explicitly collects tzdata for IANA time-zone support. GitHub Actions runs these checks on a native Windows runner. The synthetic integration check briefly registers monitoring only on the disposable CI host and collects no real app, network, DNS, or proxy activity. It does not exercise the controls interactively or establish behavior on a student computer. The workflow does not publish an unsigned download. After the Mac family flow is dependable, run the builder on Windows, then verify setup, tray visibility, task registration/restart, network collection, pairing, report transfer, sleep/wake, permissions, update and removal on supported Windows versions. Sign and validate the Windows distribution before family release.
5. **Browser and attribution research:** the optional Chromium extension now has a visible popup explaining domain-only collection, a persisted pause/resume setting, and status for its local connection. It never samples domain names in private windows. On returning to a regular window after private use, a domain-free marker breaks website-time estimates without exposing the private domain or duration. Pause and reconnect use the same marker to prevent estimates bridging unobserved intervals. Synthetic tests cover these boundaries and reconnect status. It is still not integrated into the Mac setup package. Before making a parent-friendly installer, choose and secure a stable extension ID/distribution path: Chrome native messaging requires an exact `allowed_origins` extension ID, rejects wildcards, and uses browser-specific host-manifest locations. Then bundle the extension and bridge, register/unregister the host transactionally, and validate real Chrome/Chromium installation, reconnects, private-window exclusion, pause behavior, and removal. Chrome's official guide directs local unpacked installs through the Extensions page's Developer mode; the project must not present that developer workflow as an easy family installer. See [Chrome native messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging) and [Chrome's unpacked-extension guide](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world). On macOS, a default-off experimental process traffic summary now uses `nettop` with only process labels and byte counters. It was validated with the frozen agent and repeated synthetic HTTPS requests on the test Mac; the encrypted report decrypted into Python process totals, and the ciphertext contained no domain string. The install checkbox is opt-in. This is process association, not website attribution: helper processes may own connections, brief connections and the initial counter baseline can be missed, and the data has no interface or school/home breakdown. Keep it experimental pending broader app and tunnel testing; it cannot establish which website used the bytes. Do not attribute interface bytes to sites or apps unless defensible measurements become available.
6. **Family validation and release readiness:** test installation and weekly review with nontechnical parents and children; complete accessibility, security, privacy, and age-appropriate European children's rights review; validate retention, deletion, export, recovery, upgrades, and support. [PRIVACY-AND-CHILDREN.md](PRIVACY-AND-CHILDREN.md) records engineering requirements and questions for qualified counsel; this is not a compliance determination. Gate family distribution on signed/notarized Mac and signed Windows packages with validated install/update/removal paths. A developer-only conversion command creates a parent-key-encrypted copy of the known legacy plaintext activity schema, applies retention to original timestamps, and leaves the source for verification and separate deletion. A read-only audit found no SQLite activity files in the current workspace, the ignored preview archive, or the test Mac’s expected app data directory; retain the audit and verified-conversion checklist for backups, alternate paths, and future devices. Linux remains a low-priority development/test host, never a student-facing target.

Explain collected data and measurement limits in plain language, meet accessibility basics, verify navigation/assets/links under a GitHub repository subpath, and show release readiness on every entry point. Do not publish an install download until the supported release gate is met. Once the repository is on GitHub, enable Pages from `main/docs`, review desktop and mobile rendering in a real browser, fix issues, and keep screenshots and instructions current with each user-facing change.
   - **Parent access and pairing usability:** new setups use a six-digit parent PIN to keep access private from the child; explain that this is not strong protection if someone copies a recovery file. Older recovery files remain readable with their original phrase. Initial setup and report return now use local UDP discovery with a two-digit nearby code and the existing pinned-TLS transport.
